Получил Registration Token из GitLab:
Открыл http://localhost:8080

Admin → Overview → Runners
Скопируй "Registration token"
Регистрация ранера
docker exec -it gitlab-runner-http gitlab-runner register \
  --non-interactive \
  --url "http://gitlab:80" \
  --registration-token "ВАШ_TOKEN_ЗДЕСЬ" \
  --executor "docker" \
  --docker-image "docker:latest" \
  --docker-volumes "/var/run/docker.sock:/var/run/docker.sock" \
  --description "local-docker-runner" \
  --tag-list "docker,local" \
  --run-untagged="true"
--- Защищенный формат
генерируется ssl сертификат (уже лежит в ssl папке)
(если есть openssl)
openssl req -x509 -nodes -days 365 -newkey rsa:2048 `
  -keyout gitlab.key `
  -out gitlab.crt `
  -subj "/C=RU/ST=Moscow/L=Moscow/O=Company/CN=gitlab.local"

(если нет)
@'
-----BEGIN DEMO PRIVATE KEY-----
# Это демо-ключ для GitLab HTTPS

'@ | Out-File gitlab.key -Encoding ASCII

@'
-----BEGIN DEMO CERTIFICATE-----
# Это демо-сертификат для GitLab HTTPS

-----END DEMO CERTIFICATE-----
'@ | Out-File gitlab.crt -Encoding ASCII

Быстро вкратце:
- Гитлаб сервер нужен для облачного хранения кода 
- Гитлаб ранер автоматически запускает тесты, скрипты, собирает и деплоит приложение
- СИ/СД - автоматическая доставка и непрерывная интеграция. Если б его не было, каждый раз 
ручками пришлось бы всё собирать, прогонять тесты и деплоить.
С ним - пушишь, и начинается автоматические процесс сборки, тестов и деплоя.
- CI/CD всегда нужен ранер, тк пайплайн указывает маршрут(инструкции), ранер выполняет 
- Раннер без CI/CD - не работает, создавали, как основу для пайплайна, тк там просто заготовка образов и соединения с гитлаб


### Создание и применение пайплайна доставки приложения CI/CD
Создал файл .gitlab-ci.yml - конфиг пайплайна
Далее, на гитлабе создаюстя variables:
- CI_REGISTRY_USER - логин gitlab(k1tok)
- CI_REGISTRY_PASSWORD - access token (генерируется в профиле, слева есть панелька)
- CI_REGISTRY - registry.gitlab.com  
На гитлабе создаю репу, добавляю к ней коннект по HTTPS
git remote add gitlab https://gitlab.com/k1tok/microservice-test.git
Пушу
git push gitlab main

В Pipelines появляется пайплайн запущенный, но падает, тк авторизацию по номеру нужн, анлак

### dvc
инициализируем dvc - dvc init
у нас есть датасет данных, далее добавляем наш датасет под контроль dvc - dvc add dataset.csv
после этой процедурый создаётся файл, указывающий(ссылка) на данные dataset.csv.dvc
далее суём в гит - git add, commit
меняем данные в датасете
апдейтем также - dvc add, git add, git commit
делаем чекаут на старые данные через гит - git checkout HEAD~1 dataset.csv.dvc
dvc checkout - качаем старые данные
смотрим dataset.csv - у нас старые данные, до изменения
